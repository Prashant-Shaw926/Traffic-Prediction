3. Endpoint
POST /api/simulation
Request: {"datetime": "2017-06-15T10:00:00"}

The route checks for a JSON object, then simulation_response calls run_simulation. It does not calculate correlations or influence itself.

Success JSON keeps these fields separate:
- junctions[].predicted_traffic — Spatial GRU output
- junctions[].historical_traffic — observed vehicles at T, or null
- junctions[].incoming_influence — Stage 3 influence index
- relationships[].correlation and absolute_correlation — Stage 2 lagged association
- influence_result.metadata.score_kind = influence_index
- metadata.historical_simulation = true
- metadata.model, features, lookback, relationship_method, supported_lags, window bounds, dataset_end

5. Error handling
Missing datetime: HTTP 400, "Missing request fields: datetime is required."
Malformed datetime: HTTP 400, "Invalid datetime."
Non-hourly timestamp: HTTP 400, "Datetime must be aligned to a full hour."
2017-01-01T00:00:00: HTTP 400, "Insufficient historical data for the requested simulation timestamp."
2017-07-01T10:00:00: HTTP 400, "The historical dataset ends at 2017-06-30 23:00 and does not contain sufficient data for this timestamp."
Other exceptions are not converted into a success body.
