3. Components and API client
- runSimulation posts { datetime } to POST /api/simulation through VITE_API_BASE_URL.
- A datetime-local value of YYYY-MM-DDTHH:mm is sent with :00 appended.
- HTTP 400 shows the backend error string.
- SimulationPanel owns the timestamp, clears the previous result when a request starts, and disables Run Simulation while the request is in flight.
- TrafficNetwork draws one node per returned junction and one arrow per returned relationship.
- The inspector lists junction cards, the selected relationship, influence contributions, and metadata.

4. API fields consumed
timestamp, junctions[].junction_id, predicted_traffic, historical_traffic, incoming_influence, valid_source_count,
relationships[].source_junction, target_junction, lag_hours, correlation, absolute_correlation, paired_observations, window_start, window_end,
influence_result.metadata.score_kind, formula, description,
influence_result.junction_influences[].incoming_influence, valid_source_count, contributions[],
influence_result.excluded_contributions[].reason,
metadata.historical_simulation, model, features, lookback, relationship_method, supported_lags, window_start, window_end, influence_score_kind, dataset_end.

historical_traffic and incoming_influence are number or null. The UI does not recompute Pearson correlation or the influence formula.

5. How the network is drawn
Node positions come from the returned junction ids, arranged around a circle. For four junctions that places one node at each corner of a diamond. That layout is display-only and is not a road map or GPS.
Each relationships item becomes an SVG line with an arrowhead from source to target. Stroke width and opacity follow absolute_correlation. The signed correlation and lag are written in the selected-relationship panel and in the relationship list. A legend states that thickness is absolute correlation and the arrow is direction.
