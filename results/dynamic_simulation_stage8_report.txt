3. Negative-correlation tests
ml/simulation/tests/test_stage8.py uses in-memory hourly series and a test-only SimulationConfig. Production config.py was not changed.

- A lag-1 series with correlation -1.0 beat a weaker lag-2 absolute correlation. The selected signed value stayed negative. absolute_correlation equalled its absolute value.
- When lag 1 and lag 2 both had absolute correlation 1.0, the earlier lag (1) was kept. Its signed correlation stayed negative.

4. Missing and excluded contributions
The same module built one source with the exact hour at T - 1 and another source without that hour.
The missing source was excluded with reason "missing exact source observation".
It was not stored as vehicle count 0 and was not added into the total.
The target influence index equalled the sum of the included contribution only.
Junction 4 had no included contributions, so incoming_influence stayed None and valid_source_count stayed 0.
A separate test applied the influence formula to a selected negative relationship: the weight was the absolute correlation, signed_correlation stayed negative, and contribution equalled weight times the raw source count at T - lag.

5. Duplicate-submission protection
Defect: status === 'loading' updates only after React commits, so two click() calls in one page.evaluate could both start POST /api/simulation. Stage 7 measured that.
Fix: SimulationPanel sets a useRef true before runSimulation and clears it in finally. An empty datetime-local value still returns before the ref is set. The loading label, result clearing, and backend error text are unchanged.
Browser evidence after the fix, with the response delayed:
- Two synchronous click() calls: 1 request.
- A later Run Simulation after that request finished: 1 additional request (2 total).
- A browser double-click: 1 request, button disabled, label Running….
No npm unit test exists for this. The check above is the Playwright session, not a package.json test.
