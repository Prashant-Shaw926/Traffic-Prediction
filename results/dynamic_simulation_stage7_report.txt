Stage 7 dynamic simulation integration, consistency, and reproducibility
Generated from unittest runs and a browser session against Flask and Vite.
This is a historical simulation. It is not an external live traffic feed, and the relationships are lagged statistical associations, not roads or causes.
The dataset ends at 2017-06-30 23:00:00.
No production formula, model, scaler, dataset, or /api/predict code was changed. No UI defect required a code change.

3. Relationships
Each timestamp produced 12 directed relationships, one for every ordered pair among junctions 1-4. All four relationship signatures differed. None of the six pairs of timestamps was identical. That is a measured result, not a requirement that every timestamp must differ.
Every relationship's lag was one of the configured lags (1, 2, 3, 24, 168). Paired observations were 167 for lag 1 and 144 for lag 24, both above the configured minimum of 24. Lag 168 was not selected inside these 168-hour windows.
Selected correlations on these four timestamps were all positive. Absolute correlation equalled the absolute value of the signed correlation, so the sign was preserved. These windows simply did not select a negative correlation.
The engine result for each timestamp matched a fresh discover_relationships and calculate_traffic_influence on that timestamp's window. The values are not timestamp-specific constants in the source.

5. Reproducibility
A second run_simulation for 2017-06-15 10:00:00 and for 2017-06-25 10:00:00 matched the first run: same relationships, same influence result, same metadata, same historical traffic and influence totals, and predicted traffic equal to 6 decimal places.
Two POST /api/simulation bodies for each of those timestamps were equal to each other.

6. Python engine versus Flask
For both repeat timestamps, the test-client JSON equalled simulation_response for the same datetime. Junction predictions, historical values, influence totals, relationship correlations, lags, paired counts, contribution amounts, source traffic, and signed correlations matched the engine within an absolute tolerance of 1e-12. No larger float gap appeared, so the tolerance was not relaxed.

7. Influence formula
Checked in test_influence_arithmetic_uses_raw_lagged_traffic against the implementation:
contribution = absolute_correlation * V_source(T - lag_hours)
For every included contribution on all four timestamps, the lag and signed correlation matched the selected relationship, the source traffic equalled the raw CSV value at that exact source timestamp, and the contribution matched the product. The junction influence index matched the sum of its included contributions. An excluded missing-source row would have to be absent from that raw lookup and absent from the sum. These four timestamps included every selected relationship (3 sources on each junction, 12 relationships), so there was no excluded row to display. Missing hours were not inserted as zero.

8. Browser and UI synchronization
Flask was already serving http://127.0.0.1:5000 and Vite was already serving http://localhost:5173. Edge, headless, opened the simulation view.

For 2017-06-15T10:00, 2017-06-25T10:00, 2017-06-15T18:00, and 2017-06-20T08:00 the UI comparison against that response found no mismatches. Each response had 4 nodes and 12 edges. Every returned relationship id was drawn. The selected panel showed the first relationship's signed correlation to 3 decimals, its absolute correlation, and its lag. Junction cards showed predicted traffic, historical traffic, and the influence index as separate figures. The first contribution line and the model, feature count, and lookback metadata were present. The inspector showed that response's window end. Changing the timestamp replaced the network with the new response.

A browser double-click on Run Simulation, with the response delayed, sent 1 POST. The button was disabled and read "Running…". A second user click is not accepted while that request is in flight. No UI change was made.
A script that called the button's click method twice inside one page.evaluate, before React committed, did start 2 requests. That is not the browser double-click path. After a normal click the control is disabled, so a later click does not submit and an older response is not left on screen as the new timestamp.

13. Defects, fixes, and limitations
No production defect was fixed. The loading guard blocks a real double-click.
Keras emitted a NumPy copy-keyword deprecation warning during inference. The assertions still passed. The warning was not changed.
These four timestamps did not produce a negative selected correlation and did not exclude a contribution. Sign handling and exclusion are still covered by the assertions and by the earlier Stage 2 and Stage 3 tests, but this run did not display a negative edge or an excluded row in the UI.
The same-stack evaluate double click described in section 8 is a scripted path, not the control's browser behavior.
